# Assumptions and implementation choices

The Arabic specification and supplied Ashour engineering plan guide this implementation. The plan's A1–A18 defaults are reflected in `packages/shared/src/constants.ts`. PIN is configured through the server environment. Game settings are edited in the admin settings form (with an advanced JSON editor) before a round starts.

- The plan's portable **team-code check-in** supersedes fixed-PC assignment in the Arabic specification. A device is bound to one team until checkout, next round or admin kick. Offline assignments stay reserved. Four physical seats are supported.
- Three-stage topology and counts (48/12/3, sets of 10, 8 and 15, reserve target 21) remain fixed. Points, durations, speed-tier rewards, card reuse limits, joker position, unanswered policy, grace (0–1,000 ms), automation, sound and Stage-2 grouping are configurable. Time-tier cutoffs remain 90/100/110 s to match tested boundaries.
- Accepted text/numeric answers are grading references; they are not auto-normalized/auto-graded. MCQ is graded automatically.
- Simultaneous correct receipts reaching the ladder top are sorted by monotonic microseconds. Exact ties repeat a reserve question instead of choosing by team ID. Tie-breakers leave scores unchanged.
- Ladder victory is finalized at reveal after all submissions/time expiry and manual grades. This preserves simultaneous-question arbitration and the audience phase. The question cannot advance before this decision.
- Question selection uses `crypto.randomInt`. Shared Stage-2/3 question events are serialized once and sent synchronously to eligible team sockets before individual snapshots. Client clocks affect rendering only, never acceptance/scoring. Network arrival cannot be guaranteed to have zero spread.
- Countdown hides questions and releases them when the active answer timer starts. This avoids accidentally exposing content before timing begins.
- Blitz leak replacement rewinds affected set progress, reverses subsequent answers and completed-set bonuses, and retains the round's master clock. Non-Blitz leaks replace the current question and start a fresh question timer. Reserve defaults prefer hard/joker; the operator chooses a genuinely harder replacement where needed. Joker points remain tied to question difficulty, including replacement content.
- Completed rounds/results are immutable because downstream qualifications depend on them. Arbitrary action undo is not implemented: undo covers audited manual score adjustments only. Manual ladder edits are disabled.
- SQLite keeps a versioned `match_state` document for rounds/brackets/settings and JSON question records, plus normalized teams, devices, answers, command deduplication, event log and append-only ledger. This is a compact version of the proposed relational schema. The migration is idempotent; all engine mutations remain transactional. Domain identifiers use round keys and question IDs instead of separate `round_questions` rows.
- Recovered active play/countdown is paused. Remaining active time is checkpointed every 250 ms; abrupt power loss may lose up to one checkpoint interval of timer accuracy, while previously committed answers/scores persist. Clock scoring during pause excludes paused wall time.
- Backups use SQLite's online backup API, not copying an open WAL database. Keep the most recent 20; perform them every 30 seconds and after phase changes. Manual backup download uses the same path.
- Fastify, raw `ws`, React/Vite and strict TypeScript follow the plan. Plain responsive CSS (design tokens, keyframes, CSS transitions and a canvas confetti layer) is used instead of Tailwind/Framer Motion, and a React connection hook instead of Zustand. Tajawal font files (Arabic and Latin subsets) are bundled. Audio is synthesized locally through Web Audio (countdown beeps, chimes, slot-machine ticks, ladder steps, drum roll, fanfare) instead of shipping recordings.
- Auto mode schedules start, card/question start, reveal and next question. Results remain on screen until the operator chooses next round, giving the presenter control over team changes. Assisted and manual both require operator confirmation of these transitions.
- No Internet dependencies at runtime (QR codes are generated in the browser and terminal). Browser fullscreen/kiosk is operator configured. Team devices block the context menu and the Back button (history trap) but cannot stop OS-level shortcuts; use a kiosk browser profile for that.
- Team logos are stored in SQLite (resized to 256 px PNG in the admin browser, 400 KB cap, PNG/JPEG/WebP only, never SVG) and served from `/logo/:id?v=<version>` with immutable caching. Logos are never embedded in WebSocket snapshots.
- The bracket draw tool edits a local draft (drag a team onto another to swap, or crypto-random shuffle) and commits the whole draw in one atomic `bracket.bulk` command; duplicate teams are rejected and nothing changes on failure.
- The projector may hide live Blitz scores (`liveScores` setting, default on). When off the display shows progress only until the round ends, so the room cannot infer who is right or wrong while teams are still playing.
- Visual-only effects (streak toasts, rank arrows, score deltas, wheel animation) are derived on the display from consecutive server snapshots and the server's `spinAt` timestamp. They never feed back into scoring, and the wheel lands on the category the server already chose.
- English is available as an optional locale (`?lang=en`, or the language button in the console). The language is fixed per page load; layouts mirror automatically (logical CSS properties, direction-aware arrows). Arabic is the default and the reviewed copy.
- Fractions use "7 من 15" ("7 of 15") instead of a bare slash so RTL readers cannot misread the order.
- The default bank uses all 112 questions from `أسئلة عاشور.xlsx` across 180 slots, reusing content across rounds with added multiple-choice distractors. Source difficulties are retained except hard questions assigned to joker slots. Gambler and tie-breaker answers are manually graded. The separate demo seed supports deterministic engine tests and rehearsals. Team names/codes remain sequential placeholders.
- Local HTTP/WS with a PIN/device token is intended for a trusted wired LAN. The code does not provide public Internet authentication or TLS termination. Device-token authentication for admin HTTP exports is separate from the PIN input, and tokens are stored hashed in SQLite.

Physical real-router rehearsal, Windows execution and actual WAN-disconnected testing cannot be certified by cloud/loopback/browser tests. Use `docs/rehearsal-checklist.md` before the event.
